# ADR 0001: 초기 기술 스택 선정

- 상태: 확정(MVP 기준, 재검토 가능)
- 날짜: 2026-09-10

## 배경
9개 부동산 지표를 정기 수집 → 저장 → 가중 스코어링 → 대시보드 표시하는 개인용 앱.
데이터 소스 대부분이 정부/민간 통계 사이트(한국부동산원, 국토부, 지지옥션 등)로,
공식 API가 없는 곳이 있어 크롤링/배치 수집이 필요.

## 결정
| 레이어 | 선택 | 이유 |
|---|---|---|
| 프론트엔드 | Next.js(App Router) + TypeScript + Tailwind | 대시보드형 SPA에 적합, Vercel 배포 용이, 컴포넌트 재사용성 |
| 차트 | Recharts | React 생태계 표준급, 학습 곡선 낮음 |
| 데이터 수집 | Python (requests/httpx, BeautifulSoup, pandas) | 크롤링·데이터 정제 생태계가 JS보다 성숙 |
| 저장소 | SQLite (MVP) | 개인 프로젝트 규모에서 별도 DB 서버 불필요, 파일 기반으로 백업 용이. 사용자 다수·동시성 필요해지면 Postgres로 이관 |
| 배포 | 미확정 (Vercel 후보) | 수집 배치를 어디서 돌릴지(Vercel Cron vs 로컬 스케줄러)에 따라 달라짐 |

## 대안 검토
- **풀스택을 Python(Django/FastAPI)으로 통일**: 데이터 수집과 언어를 맞출 수 있으나, 대시보드 UI/차트 생산성은 Next.js가 우세하다고 판단해 기각.
- **DB를 처음부터 Postgres로**: 개인 프로젝트 초기 단계에 과한 인프라. SQLite로 시작 후 필요 시 이관.

## 영향
- 프론트(Next.js)와 데이터 파이프라인(Python)이 SQLite 파일을 통해 통신 — API 계층을 Next.js API Route로 둘지, 별도 서비스로 둘지는 추후 ADR에서 결정.

## 재검토 시점
- 사용자가 여러 명(가족 공유 등)으로 늘어나거나 실시간 동시 편집이 필요해지면 Postgres + 별도 백엔드 재검토.
