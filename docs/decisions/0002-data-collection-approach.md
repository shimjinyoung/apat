# ADR 0002: 지표 수집 방식 — API 우선, robots.txt 위반 스크래핑 금지

- 상태: 확정
- 날짜: 2026-09-10

## 배경
9개 지표 중 다수가 공식 API 없이 화면 조회만 제공한다. 파이프라인 구현 전 각 출처 사이트의
`robots.txt`를 확인한 결과, 지지옥션(`ggi.co.kr`)은 `Disallow: /`로 전체 크롤링을 차단하고 있고,
한국부동산원(`reb.or.kr`)도 실제 통계 조회 경로(`/r-one/statistics/`)를 명시적으로 차단하고 있음을 확인했다.

## 결정
1. **robots.txt가 차단한 경로는 스크래핑하지 않는다** (CLAUDE.md 불변식 §1-5).
2. 공식 Open API가 있는 지표(매매거래량 — data.go.kr, 미분양 — KOSIS 경유)는 **API로 자동 수집**한다.
3. API 파라미터(tblId 등)를 확신할 수 없는 지표는 **틀린 값을 하드코딩하지 않고 TODO로 남긴다.**
4. 자동 수집이 불가능하거나(robots.txt 차단) 신뢰할 단일 API가 없는 지표(경매 3종, 입주물량)는
   **`manual_readings.json` 수동 입력**으로 운영한다. 사람이 공식 보도자료를 보고 채워 넣으면
   파이프라인이 그대로 DB에 반영한다.
5. API 키(MOLIT, KOSIS)는 **사용자 본인이 직접 회원가입해 발급**받는다. Claude는 대신 계정을
   생성하지 않는다(세션 공통 원칙).

## 영향
- 9개 지표 중 즉시 완전 자동화되는 것은 2개(거래량, 미분양)뿐이다. 나머지는 수동 또는 TODO 상태.
- 대시보드(`web/`)는 당분간 `data/sample-readings.ts`(수동 스코어링 포함 샘플)를 계속 사용하고,
  파이프라인 결과(`export_json.py` 산출물)는 검증용으로만 병행한다.
- `-1/0/+1` 채점(트렌드 판정) 로직은 이 ADR의 범위가 아니다 — 여전히 `web/lib/scoring.ts`에서만
  다루며, Python 파이프라인은 원자료(raw value) 수집까지만 책임진다.

## 재검토 시점
- KOSIS tblId 확인 등 TODO가 해소되면 이 문서와 `docs/data-sources.md`를 함께 갱신한다.
- 지지옥션 유료 API/제휴가 확인되면 수동 입력 항목을 자동화로 전환 검토.
